## Stage 2 Decisions

- Generate snapshots current assignments without mutating live assignments.
- Generated records are hidden later by scoped board filtering; cancel removes only
  that module's generated snapshot and therefore reveals its live assignments again.
- Save converts only an existing generated record and never rewrites a saved record.
- Delivery vehicle data is snapshot-only and absent from OP SHOP Collection models.
- New locks query only their corresponding new `SAVED` table.
- Legacy assignment and Final Summary behavior remains unchanged until new scoped
  workflows are wired in later stages.
- OP SHOP Collection rows now preserve call-before and call-timing data through an
  additive, idempotent old-pilot-DB column upgrade.

## Stage 3 Decisions

- Dry-run opens SQLite read-only and is always the default.
- Apply requires both `--apply` and `--yes`.
- Any legacy `GENERATED` summary or workspace conflict blocks the entire apply.
- Apply creates and integrity-checks a timestamped backup before writes.
- All new workspace snapshot writes share one transaction.
- Legacy Final Summary headers and rows remain unchanged.
- Historical OP SHOP call-before fields use false/null rather than live enrichment.
- Deterministic IDs plus `legacy_summary_id` markers make reruns idempotent.

## Stage 4 Decisions

- Delivery board reads Orders, Delivery assignments, Delivery vehicle selections,
  and Delivery Run Sheets only.
- OP SHOP board owns Regular task ensure and reads OP SHOP tasks/templates/groups
  plus OP SHOP Pickup Collections only.
- Scoped boards never call or reshape the legacy shared board.
- Generated and saved reserved task filtering is module-specific and read-only.
- Only saved Delivery Run Sheets produce vehicle lock entries.
- Shared specifications returns drivers and vehicles without task generation.

## Stage 5 Decisions

- Delivery mutations always operate on `ORDER`; OP SHOP mutations always operate
  on `OPSHOP_PICKUP` and do not accept a public `trip_no`.
- OP SHOP assignments retain storage compatibility by writing internal `trip1`.
- Generated snapshots reserve captured tasks, their driver/date target, and (for
  Delivery) vehicle selection until the generated snapshot is cancelled.
- Saved snapshots enforce the same boundaries with explicit saved-state errors.
- Delivery mutations consult only Delivery Run Sheets; OP SHOP mutations consult
  only OP SHOP Pickup Collections.
- OP SHOP batch and Countryside route-group changes preflight every row before a
  single repository transaction writes tasks and assignments.
- Legacy assignment, vehicle, Final Summary, board, and frontend paths remain unchanged.

## Stage 6A Decisions

- Login and registration success replace the current hash with `#home`.
- Empty, invalid, and three legacy hashes resolve to approved workspace routes.
- Logged-out users render only the auth gate and trigger no workspace data load.
- Home is navigation-only and does not eagerly load either scoped board.
- Delivery routes call only Delivery board/run-sheet plus shared specification reads.
- OP SHOP routes call only OP SHOP board/collection plus shared specification reads.
- Dedicated renderers are read-only; legacy renderers/actions remain in source but are
  not mounted by the new workspace shell.
- The new navigation and page titles do not use the legacy Final Summary name.
- Browser QA uses a temporary seeded SQLite database and leaves no local artifact.
